# Импорт трёх наборов Ultralytics

Используются предоставленные пользователем `helmet.ndjson`,
`cigarette.ndjson`, `fangchen.ndjson`. Они содержат аннотации и ссылки
на изображения, а не сами изображения. Экспорты исключены из Git;
копия каждого сохраняется в соответствующем raw-каталоге.

Из корня репозитория:

```bash
PYTHONPATH=ml ml/.venv-gate/bin/python -u -m train.platform_import \
  cigarette.ndjson fangchen.ndjson helmet.ndjson \
  --out ml/data/finetune-v2/raw --workers 8 --curl
```

`--curl` использует системный curl с HTTP/2 и пулом соединений.
Без этого флага доступен загрузчик на стандартной библиотеке Python.
Существующие изображения не скачиваются повторно. Новые файлы сначала
пишутся в `.part`; curl продвигает их в окончательные имена только после
успешного HTTP 200. Для каждой записи затем проверяются декодирование,
размер кадра, SHA256 и pHash. Исходные аннотации не исправляются на месте.

На каждый набор создаются:

- `source.ndjson` — неизменённый экспорт пользователя;
- `images/` — исходные изображения с безопасными именами по номеру строки;
- `audit.json` — результаты проверки, соответствие исходным именам,
  исходный split, ошибки bbox и строки целевой YOLO-разметки;
- `transfers.tsv` — локальные пути и статусы curl, без URL изображений.

При повторном запуске SHA256 экспорта должен совпадать с сохранённым
snapshot. Для нового экспорта использовать новый выходной каталог.
Сами ссылки остаются только в исключённых из Git исходных данных.

Сопоставление классов определяется `platform_sources.yaml` и проверяется
по заголовку каждого экспорта. Mask → face_protection; Coverall не является
защитой лица. Face и smoking не подменяют head и cigarette.

Правила автоматической проверки:

1. Некорректные числа, неизвестные классы, неположительные размеры и
   существенный выход bbox за кадр — ошибка.
2. Малый выход края не более `1e-4` из-за округления экспортированных
   координат обрезается до границы, счётчик сохраняется. Это техническая
   нормализация, не ручная переразметка.
3. Изображение с некорректным bbox целевого класса получает
   `quarantined_invalid_target_bbox`, даже если есть другие корректные bbox.
   В Fangchen встречаются исходные `[class, 2, 2, 2, 2]`.
4. Ошибка в неиспользуемом вспомогательном классе сохраняется в отчёте,
   но не превращается в целевой объект.
5. Пустые метки или отсутствие целевого класса получают
   `unverified_negative_or_unlabelled`. Это не подтверждённый негатив.
6. `source_target_labels_valid_partial_classes` означает только корректность
   предоставленных целевых рамок. Отсутствие других наших классов в кадре
   этим не доказано.

Все записи остаются `eligible_for_training=false` до проверки дубликатов,
подготовки окончательных split и выбора способа работы с частичной
разметкой разных классов в трёх источниках. Этот импорт не запускает
обучение и не меняет рабочую модель или контракты событий.

## Подготовленный набор и ручной запуск обучения

Все 20518 исходных изображений скачаны, ошибок декодирования нет.
Входной аудит дал 5235 кадров Helmet, 2324 Cigarette и 881 Fangchen с
корректными целевыми метками. Некорректные Mask bbox и не проверенные
негативы не вошли в обучающую сборку. После группировки исключены ещё
24 изображения, связанные со старым val. Итог: **5896 train / 1267 val /
1253 test**, только из трёх новых источников, без ручных SH17/pics и replay.

Данные: `ml/data/finetune-v2/dataset/`, конфигурация `data.yaml`, полный
журнал `manifest.json`. Сводка в Git: `annotations/platform-v2-summary.json`.
Существующие веса остаются в `ml/runs/release-ppe-s/best.pt`.

Проверка без обучения:

```bash
PYTHONPATH=ml ml/.venv/bin/python -m train.platform_train --check
```

Ручной запуск из корня репозитория в ветке Vladimir:

```bash
PYTHONPATH=ml ml/.venv/bin/python -u -m train.platform_train --epochs 20 --batch 8 --name ppe-v3
```

Эта команда дообучает существующий ppe-v2, а не случайную модель. Все 499
тензоров весов проверены при загрузке: значения до старта сохраняются;
название выхода 3 расширяется до face_protection. Параметры: 640 px,
AdamW, lr0=0.0003, batch 8, FP32, early stopping patience=7, workers=0.
Смешивание кадров (mosaic/mixup/cutmix/copy_paste) отключено, чтобы не
смешивать разные наборы доступных классов. Остальные обычные аугментации
Ultralytics сохраняются; фактические параметры будут в args.yaml.

`source_training.py` маскирует classification loss по источнику:
Helmet — классы 1/2, Cigarette — 4, Fangchen — 3. Неразмеченные классы
не становятся ложными негативами. Та же область доступной разметки
учитывается в валидации. Протестированы нулевой градиент для неизвестных
классов и ненулевой градиент для настоящих отрицательных примеров.

Результаты обычного запуска:

- `ml/runs/ppe-v3/weights/best.pt` и `last.pt`;
- `ml/runs/ppe-v3/results.csv`, `args.yaml`;
- `ml/runs/ppe-v3/metrics.json` с AP по классам на val;
- `ml/runs/ppe-v3/provenance.json` с хешем набора и стартовых весов.

Каталог прогона не перезаписывается. Test не используется при обучении.
После завершения отдельным шагом нужны test, сравнение со старым val и
экспорт/проверка ONNX. Рабочая модель не заменяется автоматически.

Фоновый конвейер отменён по просьбе пользователя. Он успел собрать данные
и baseline на новом val, но был остановлен на проверке train перед первой
эпохой. Завершённых эпох и новых checkpoint нет; исходные веса неизменны.
Baseline сохранён в `ml/data/finetune-v2/baseline-val.json`; результаты
по новому классу масок не эквивалентны прежней оценке респираторов.
