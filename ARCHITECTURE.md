# Архитектура Zorky

## Структура репозитория

| Каталог | Что внутри |
|---|---|
| `ml/` | ML-воркер на Python: `worker/` (декодирование, детектор, трекинг, правила, клиент бэкенда), `eval/` (оценка на роликах), `export/` (ONNX и сборка под LinQ), `train/` (подготовка данных и обучение) |
| `backend/` | FastAPI: `app/api` (маршруты), `app/application` (сервисы, порты), `app/domain` (модели и правила), `app/infrastructure` (SQLite, снимки, превью, сессии, пользователи) |
| `web/` | React + Vite, PWA: `src/app`, `src/domain` (чистая логика), `src/infrastructure` (API, оповещения), `src/ui` (экраны и компоненты) |
| `linq/` | Работа со стендом LinQ: VPN, Jupyter, сборка `.tpu`, сервис кадров |
| `contracts/` | Единый контракт: `openapi.yaml`, `events.schema.json`, `violation_types.json` |
| `demo/` | Ролики, мок событий, замер задержки, инструкция демо |
| `tests/` | Сквозные тесты и тесты `tasks.py`, `linq/`, контракта |
| `scripts/` | Windows-лаунчеры демо и LinQ (`demo.bat`, `linq-up.bat`, ...) |
| `docs/` | Настройка LinQ, выпуск моделей, замеры и графики |

Корень: `tasks.py` (гейты, демо, e2e, установка), `Makefile` (обёртка над ним), `docker-compose.yml`, `ruff.toml`, `.env.example`.

## Поток данных

```
видео (демо-ролики / RTSP)
   │
   ▼
ML-воркер — ml/worker, Python, рядом с LinQ
  декодирование → YOLO на LinQ → трекинг → правила (нет каски ≥ N кадров, ноги в полигоне зоны)
   │  только исходящие запросы:
   │  POST /api/events, снимки, превью, метрики
   ▼
Бэкенд — backend, FastAPI
  события, камеры, зоны → SQLite (или память в режиме разработки)
  SSE /api/stream — живая лента
  оповещение мастера — событие `master` в SSE, эскалация
   │
   ▼
Фронт — web, React
  мониторинг · журнал · редактор зон · аналитика · метрики LinQ
```

## Ключевые решения
- **Воркер только отправляет.** Входящие соединения к стенду LinQ закрыты, поэтому события, снимки, превью и метрики воркер сам шлёт в бэкенд.
- **Бэкенд не декодирует кадры.** JPEG от воркера хранит и отдаёт как есть: MJPEG-превью для `<img>`, снимки по ссылке.
- **Событие — начало нарушения у трека.** Трекинг и антидребезг (`ml/worker/rules`): нарушение должно держаться N кадров подряд, повтор по тому же треку — не раньше чем через cooldown. Без этого один человек без каски даст сотни событий в минуту.
- **Зоны рисуют во фронте, хранит бэкенд.** Воркер перечитывает их каждые несколько секунд (`GET /api/cameras/{id}/zones`).
- **Опасной зоне обучение не нужно**: готовый детектор людей + полигон.
- **Живая лента — SSE, а не WebSocket**: данные идут в одну сторону, браузер переподключается сам.
- **Метрики LinQ — на дашборде**: FPS, время инференса, задержка «кадр → событие».
- **ML и бэкенд на одном языке — Python**: типы из одного контракта.
- **Оповещения только внутри контура**: веб-приложение мастера, без Telegram и push-сервисов Google и Apple.
- **Рабочие веса СИЗ — YOLO11s/640** из Release `ppe-v2`; YOLO11n остаётся запасным вариантом.

## Безопасность
- **Вход.** Все `/api/*` кроме `/healthz` требуют сессию: логин и пароль из файла пользователей (`MOSPROM_USERS`, вне git), защита от перебора, проверка Origin. Без файла и `WORKER_TOKEN` — режим разработки, всё открыто.
- **Роли.** `master`, `operator`, `auditor`, `admin`: мастер и оператор подтверждают события, аудитор только читает, админ управляет пользователями и зонами.
- **HTTPS.** Веб отдаётся по HTTPS (порт 8443, сертификат — `py tasks.py cert`); PWA и звук оповещений работают только в защищённом контексте.
- **Токен воркера.** ML-воркер ходит с `Authorization: Bearer <WORKER_TOKEN>` и может только `POST /api/events`, `/frame`, `/snapshots`, `/metrics`.
- **Всё внутри контура.** Видео, снимки и события не уходят наружу. Секреты — только в файле окружения и `~/.mosprom`.

## Гейты и CI
`python3 tasks.py gate` запускает три гейта: `gate-ml` (ruff + pytest для `ml/`, `demo/`, `tests/`), `gate-back` (ruff + pytest + e2e для `backend/`), `gate-web` (tsc + vite build + vitest). `.github/workflows/ci.yml` гоняет те же команды по затронутым зонам.
