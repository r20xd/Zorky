# Релиз: что сделать, когда придут новые веса

Всё остальное готово и проверено; ниже — только то, что зависит от весов. Время — оценка.

## 0. Перед началом (2 минуты)

```bash
py tasks.py linq-up        # туннель до стенда + наблюдатель, сам поднимает при обрыве
py tasks.py linq-check     # LinQ ГОТОВ к работе?
```

Веса — `.onnx` со статическим входом `1x3x640x640` и без NMS внутри (экспорт и проверка:
`ml/export/linq.py`, `python -m export.linq export --ppe <best.pt> --out linq_models`).

## 1. Экран (FP32) — сразу, 1 минута

Положите новый `best.onnx` на место прежнего (`%USERPROFILE%\.mosprom\models\best.onnx`) и перезапустите
`scripts\demo.bat`. На экране распознавание улучшится без LinQ.

## 2. LinQ — сборка программы (~2,5 ч на 48 кадров, идёт сама)

```bash
py tasks.py linq-build start <best.onnx> --name ppe48 --frames 48
py tasks.py linq-build status --name ppe48      # когда хотите; команда не блокирует
```

`start` нарезает кадры из роликов (калибровка и проверка — на разных кадрах), загружает веса и
код на стенд (докачка при обрыве) и запускает сборку отдельным процессом. Калибровка на стенде
идёт ~2,5 мин на кадр: больше кадров — ближе к FP32, но дольше. Не успеваете — `--frames 24`
(~1 ч). Не закрывайте туннель: `linq-up` держит его сам.

## 3. LinQ — проверка и результаты (~10 минут)

```bash
py tasks.py linq-build finish --name ppe48
```

Копирует программу в `/auto/cache`, сравнивает с ONNX FP32 на проверочных кадрах, снимает скорость
при 1/2/4/8 запросах, скачивает отчёт (`ml/export/linq_results/ppe48_accuracy.json`) и программу
(`ml/linq_programs/`), обновляет `docs/measured.json` и перерисовывает графики `docs/img/*.svg`.
Раздел «LinQ» в дашборде сам покажет новые замеры (после перезапуска бэкенда).

## 4. Обновить цифры в README (~10 минут)

Что менять руками: числа в верхней таблице и в разделе «Замеры на LinQ» (скорость, задержка,
F1 и порог). Если F1 всё ещё ниже 0,7 — оставьте блок «Качество после квантования — без прикрас»,
он честно объясняет причину.

## 5. Гейты и коммит (~10 минут)

```bash
py tasks.py gate           # ruff, pytest, tsc, vite build, vitest
```

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `linq-check` не видит стенд | `py tasks.py linq-up` ещё раз; смотрите `linq_up.log` и `linq_watch.log` |
| Сборка упала (`status`: не идёт, код ≠ 0) | лог — `~/work/mosprom/build/<имя>/compile.log` на стенде (через Jupyter) |
| Скорость на стенде в разы хуже обычной | стенд общий; повторите замер в другое время, оба значения честно приведите в README |
| F1 низкий после новой калибровки | больше кадров калибровки или кадры ближе к целевым сценам; порог LinQ выбирайте по лучшему F1 из отчёта |
| Не успеваем собрать новую программу | на защите показывайте `ppe16` и замеры (`ml/export/linq_results/`), экран считает FP32 |
