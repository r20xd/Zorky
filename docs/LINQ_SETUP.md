# Подключение к LinQ на новом компьютере (OpenVPN + Amnezia рядом)

Цель: за 10–15 минут на любом Windows-компьютере получить туннель до стенда, который держится сам.

## Что нужно заранее (выдают организаторы)

| Что | Куда кладётся | Не класть |
|---|---|---|
| профиль OpenVPN хакатона (`*.ovpn`) | в Загрузки или в папку `linq/` — найдётся сам | в git и в чат |
| логин и пароль VPN | поля `OVPN_USER`, `OVPN_PASS` в файле окружения | в код и в логи |
| логин и пароль (или токен) Jupyter стенда | `JUPYTER_LOGIN`, `JUPYTER_PASS` или `JUPYTER_TOKEN` | — |

Профиль и пароли — секреты: в репозиторий они не попадают (так устроен `.gitignore`, а перед push их ищет сканер).
Переносите их между компьютерами флешкой или менеджером паролей, не через git и не через мессенджер.

## Шаги

1. **OpenVPN.** Поставьте OpenVPN Community (openvpn.net), с драйвером wintun или TAP. Путь по умолчанию
   `C:\Program Files\OpenVPN\bin\openvpn.exe` найдётся сам.
2. **Проект.** `py tasks.py setup` (зависимости), затем `py -m pip install websocket-client`.
3. **Доступы.** Скопируйте шаблон `.env.example` в `.env`, добавьте в него поля `LINQ_HOST`, `LINQ_USER`, `LINQ_TOKEN`, `OVPN_EXE`, `OVPN_PROFILE`, `OVPN_USER`, `OVPN_PASS`, `OVPN_SUBNET`, `JUPYTER_URL`, `JUPYTER_LOGIN`, `JUPYTER_PASS` (значения выдают организаторы) и заполните поля доступа (таблица выше).
   Файл `.env` в git не попадает.
4. **Один раз:** запустите `scripts\linq-auto-setup.bat` и подтвердите запрос Windows. Он создаёт задачи планировщика,
   после этого подключение идёт без запросов UAC и работает кнопка «Подключить» в дашборде.
5. **Проверка:** `py tasks.py linq-doctor` — по пунктам покажет, чего не хватает и что сделать.
6. **Подключение:** `py tasks.py linq-up`. Команда поднимает туннель, проверяет стенд, загружает программы `.tpu`
   и остаётся наблюдателем: если стенд пропал, туннель поднимается заново. Остановить: `py tasks.py linq-down`.

Дальше — живой поток (`py tasks.py linq-live`) и сборка программ из новых весов (`py tasks.py linq-build`, см. `docs/RELEASE.md`).

## Если рядом стоит Amnezia

Наш профиль «вежливый»: трафик идёт через OpenVPN **только до подсети стенда** (`<подсеть стенда>`), всё остальное
остаётся у Amnezia. Для этого `linq-up` сам делает три вещи:

- отключает у профиля перехват маршрута по умолчанию и DNS (`route-nopull`, `pull-filter`);
- добавляет маршруты уже, чем у Amnezia (две половины `/25`), чтобы наши побеждали;
- ставит адаптеру OpenVPN метрику 1 (нужны права администратора, поэтому `linq-up` запускается через задачу).

Если стенд всё равно не отвечает при включённой Amnezia:

1. В Amnezia выключите **Kill switch** (он режет всё мимо её туннеля) или добавьте подсеть `<подсеть стенда>`
   в исключения (раздельное туннелирование).
2. `py tasks.py linq-doctor` покажет, видит ли система адаптер Amnezia, а в `linq_up.log` будут имена фильтров
   брандмауэра, похожих на kill switch.
3. Проверьте маршруты: `route print <подсеть стенда>` — должны быть записи через шлюз `<шлюз VPN>`.
4. Последний вариант — временно отключить Amnezia, поднять `linq-up`, затем включить её обратно: уже поднятый
   туннель продолжит работать.

## Типичные ошибки

| Что видите | Причина и что делать |
|---|---|
| `Error opening 'Auth' auth file` в `.linq-run/openvpn.log` | Старая версия: удаляла файл логина раньше времени. Обновите проект; сейчас файл живёт, пока жив туннель |
| `TLS handshake failed`, тишина | профиль не тот или канал недоступен; проверьте сеть, попробуйте другой профиль от организаторов |
| `Отказано в доступе` при добавлении маршрута | нет прав администратора: запускайте через `scripts\linq-auto-setup.bat` (задачи) |
| `WSAEACCES` при обращении к стенду | фильтр kill switch другого VPN; см. раздел про Amnezia |
| `linq-doctor`: «Стенд не виден», туннель есть | подождите 20–30 с после подключения, затем `linq-up` ещё раз |
| Подключение в дашборде «идёт» дольше 5 минут | смотрите `linq_up.log` и `linq_watch.log` в корне проекта |

## Что где лежит

- `linq_up.log`, `linq_watch.log` — вывод подключения и наблюдателя (в git не попадают);
- `.linq-run/` — временные файлы OpenVPN, включая `openvpn.log` (в git не попадает; файл логина внутри
  доступен только владельцу и удаляется командой `linq-down`);
- `~/.mosprom/linq_report.json` — последний отчёт о стенде для раздела «LinQ» в дашборде.
