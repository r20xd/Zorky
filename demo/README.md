# Демо

Здесь всё, чтобы показать решение жюри без сюрпризов.

## Запуск
- Всё сразу (бэкенд + фронт + мок событий по кругу): `py tasks.py demo` на Windows, `make demo` на Mac/Linux, затем открыть http://localhost:5173.
- Со входом по ролям: `py tasks.py demo --login` — на экране входа: `operator` / `demo-operator-1` (мониторинг, очередь) и `master` / `demo-master-1` (экран мастера, на телефоне — `/master`). Пароли только для показа. Оператор и мастер входят в разных окнах (или в режиме инкогнито).
- Настоящая система с воркерами: `py tasks.py run --video demo/videos/cam1.mp4 [--ppe-weights W] [--device auto|cpu|gpu|linq]` (файлы идут по кругу, RTSP/HTTP — как есть, упавший воркер перезапускается); камеры из веба: `py tasks.py run --from-backend`.
- Только мок событий в уже запущенный бэкенд: `py demo/replay_events.py --loop`.

## Видео
Ролики тяжёлые и лежат вне git: содержимое `demo/videos/` игнорируется. Ссылка на общий диск: _вставить_.
Под каждый тип нарушения — ролик, где оно точно видно, и момент, когда оно появляется:

| Файл | Камера | Нарушение | Момент |
|---|---|---|---|
| _cam1_press.mp4_ | cam-1 | опасная зона | _0:12_ |

## Сценарий показа (≈3 минуты, черновик)
1. Проблема: оператор не уследит за десятками камер, нарушения замечают после происшествия.
2. Живой дашборд: камеры и лента нарушений.
3. Человек заходит в опасную зону → событие в ленте через пару секунд, а у мастера в сети — на экране /master.
4. Каска или респиратор на другой камере.
5. Журнал: разметка «подтверждено / ложное», статистика по типам и сменам.
6. LinQ: FPS и задержка на их ускорителе против CPU.
